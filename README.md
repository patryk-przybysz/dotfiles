# dotfiles

Personal Nix flake for my machines — [Home Manager](https://github.com/nix-community/home-manager), [NixOS](https://nixos.org/), and [system-manager](https://github.com/numtide/system-manager) configs. Structured with the dendritic pattern: [flake-parts](https://flake.parts), [flake-file](https://github.com/denful/flake-file) and [import-tree](https://github.com/vic/import-tree).

> **Not a template.** This repo is heavily vibecoded, machine-specific, and changes without notice.

## Layout

Every `.nix` file under `modules/` is a flake-parts module, loaded automatically by import-tree. Files and folders whose name starts with `_` (helpers, generated hardware configs) are skipped.

```
.
├── flake.nix              # generated by flake-file, do not edit
└── modules/
    ├── flake/             # flake plumbing: inputs, systems, nixpkgs, formatter, git hooks, devShell
    │   └── features.nix   # the features / hosts / homes options and how they become configurations
    ├── features/          # one file per feature, or a folder when it has assets
    ├── users/
    │   └── patryk.nix     # what patryk gets everywhere
    └── hosts/
        ├── an16-41/       # NixOS laptop
        ├── oci-a1/        # NixOS server (aarch64), Minecraft
        └── ubuntu-wsl/    # standalone Home Manager + system-manager
```

Everything about a feature lives in its own file: its flake inputs (`flake-file.inputs.<name>`), overlays (`nixpkgs.overlays`), its NixOS half, its Home Manager half, and any devShell. Modules use flake inputs from the file they're written in; nothing goes through `specialArgs`.

## Features, machines and users

Features, machines, users on a machine and standalone homes all have the same shape: an `includes` list of features plus optional `nixos` and `homeManager` halves. Listing a feature turns it on; there are no `enable` options.

- **Machine level:** a feature in `hosts.<machine>.includes` applies its NixOS half to the machine and its Home Manager half to every user on it.
- **User level:** a feature in `features.<user>.includes` (everywhere) or `hosts.<machine>.users.<user>.includes` (that machine only) applies its Home Manager half to that user only, and its NixOS half to the machine the user is on.
- **No duplicates:** a feature reached more than once (by the machine and a user, or by two users) is applied once.
- **No users, no Home Manager:** a machine without users doesn't load Home Manager. A standalone home (`homes."<user>@<machine>"`) gets its user's everywhere set plus its own list, and skips NixOS halves.

### Add a feature

Create `modules/features/<name>.nix` with one or both halves:

```nix
{ inputs, ... }:
{
  flake-file.inputs.foo.url = "github:someone/foo"; # only if it needs an input

  features.foo = {
    nixos = { pkgs, ... }: { programs.foo.enable = true; };
    homeManager = { pkgs, ... }: { home.packages = [ pkgs.foo ]; };
  };
}
```

Then list it somewhere, e.g. `includes = with config.features; [ foo ];`. A misspelled name fails evaluation with "undefined variable". If it added an input, regenerate `flake.nix` (see below).

### Add a machine or a user

A NixOS machine is one `hosts.<name>` block in `modules/hosts/<name>/default.nix`:

```nix
{ config, ... }:
{
  hosts.box = {
    includes = with config.features; [ nix niri ];
    nixos = {
      imports = [ ./_hardware-configuration.nix ];
      users.users.alice.isNormalUser = true;
      # ...
    };

    users.alice = {
      includes = with config.features; [ gaming ];
      homeManager.home.stateVersion = "26.05";
    };
  };
}
```

A user on a machine is `hosts.<machine>.users.<user>`, plus a `users.users.<user>` account in the machine's `nixos` half. What they get on every machine goes in `features.<user>` (see `modules/users/patryk.nix`). A standalone Home Manager config is `homes."<user>@<machine>"` with a `system`, like ubuntu-wsl.

## `flake.nix` is generated

Inputs are declared next to the code that uses them, and flake-file writes `flake.nix` from them. After adding, changing or removing an input:

```sh
nix run .#write-flake
nix flake lock
```

The `check-flake-file` check fails if `flake.nix` is out of date.
